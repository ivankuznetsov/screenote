# LLM Wiki Maintenance

TLDR: The project wiki is maintained by bounded Codex refresh scripts. Agents read `wiki/index.md`, search the project wiki, search the configured main wiki path when present, update project pages, and write append-only fragments under `wiki/log.d/`; compiled `wiki/log.md` is generated by the wrapper tooling.

## Configuration

`.llm-wiki/config.json` configures:

- `headless_agent: "codex"` for unattended refreshes.
- `context_agents`: `claude`, `codex`, and `pi`.
- `main_wiki_path: /home/asterio/wikis/master/wiki`.
- `created_by: hive`.

As of the 2026-07-08 refresh, `/home/asterio/wikis/master/wiki` and the default main wiki paths checked by the refresh prompt were not present on this machine. Record cross-project uncertainty in [[gaps]] when that path is unavailable.

## Manual Refresh

`.llm-wiki/refresh-wiki.sh`:

1. Resolves a writable QMD cache directory, falling back to `.llm-wiki/qmd-cache` when the default cache is not writable.
2. Clears repository-local Git environment variables before invoking external tools.
3. Locates QMD from `HIVE_QMD_BIN`, `PATH`, Hive-managed install paths, or the Hive install-prefix file.
4. Runs bounded `qmd update` before Codex when QMD is available.
5. Runs `codex exec` with access to the QMD cache and the project root.
6. Runs bounded `qmd update` and `qmd embed --max-docs-per-batch 64 --max-batch-mb 64` after Codex finishes.

The Codex prompt explicitly tells the agent not to run `qmd update` or `qmd embed`; the script owns those maintenance commands.

## Post-Commit Refresh

`.llm-wiki/post-commit-refresh.sh` is worktree-safe:

- A commit in any worktree can trigger refresh, but wiki writes happen on the main checkout.
- A lock under the shared Git directory serializes refreshes across worktrees and can reclaim stale locks after the configured TTL.
- Linked-worktree runs prepend a redirect directive that tells the agent to read feature code from the committing tree but edit wiki files only in the main checkout.
- Refresh scope is selected from changed paths: schema/model/entity, route/controller/command, dependency, and docs/plans/context/wiki changes.
- The wrapper runs QMD maintenance after a refresh and commits only `wiki/` changes with the post-commit hook disabled.
- It touches sync marker files under known wiki sync directories when those directories exist.

The wrapper intentionally does not push wiki-refresh commits.

## Log Compilation

`.llm-wiki/compile-log.sh` compiles `wiki/log.md` from append-only `wiki/log.d/*.md` fragments:

- Fragments are sorted newest-first using `LC_ALL=C sort -r`.
- Empty fragments are ignored.
- A generated block is inserted between `<!-- BEGIN GENERATED WIKI LOG FRAGMENTS -->` and `<!-- END GENERATED WIKI LOG FRAGMENTS -->`.
- Legacy hand-written `##` entries from older wiki history are preserved after the generated block.

Feature and refresh work should add a fragment under `wiki/log.d/` and avoid editing compiled `wiki/log.md` directly.

## Agent Context

`AGENTS.md` and `CLAUDE.md` both contain the managed LLM Wiki block. The block tells agents to read `wiki/index.md`, search the project wiki, search the configured main wiki path when present, update affected pages when behavior changes, add a `wiki/log.d/` fragment, and record uncertainty in [[gaps]].

Claude session-start hooks in `.claude/settings.json` print wiki index and log excerpts, but the file currently contains overlapping startup hooks from separate bootstrap generations. Treat that as an automation cleanup candidate rather than product behavior.
